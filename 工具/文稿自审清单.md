# 文稿自审清单

> 每份文稿交付前，逐项核对。这不是可选的——是必须过的闸门。

---

## 一、事实核查

- [ ] **数据准确** — 所有数字（人数、LOC、时间、阶段数）与 spec/plan 文档一致？
- [ ] **决策追溯** — 引用的设计决策可在 brainstorm/spec 中找到出处？
- [ ] **项目定位** — 对项目范围的描述与 Phase A 确认的 22 项决策一致？
- [ ] **团队信息** — 人数、水平分布、时间安排与实际团队情况一致？

## 二、概念核查

- [ ] **术语使用正确** — 技术术语（DAG、Supervisor、Cell、MCP）用法与 spec 一致？
- [ ] **概念层次正确** — 没有把不同层级的概念并列？（如：CTF 是竞赛形式，不是安全领域）
- [ ] **因果关系正确** — 解释"为什么"的逻辑链条经得起推敲？
- [ ] **没有过度承诺** — 没把 Phase 5 的功能说成 Phase 1 就能用的？

## 三、结构核查

- [ ] **有明确的主题句** — 每节能用一句话说清在讲什么？
- [ ] **信息不重复** — 同一件事没在多个地方反复讲？
- [ ] **逻辑流顺畅** — 从"是什么"→"为什么"→"怎么做"→"谁来做"自然推进？
- [ ] **长度可控** — 每条内容都服务于会议目的，没有离题？

## 四、受众核查

- [ ] **面向听众** — 解释方式适合团队成员的水平？（有人零基础，有人打过比赛）
- [ ] **可执行** — 听完之后知道回去要做什么具体动作？
- [ ] **减少 jargon** — 能不用的英文缩写就不用，用了的第一次出现时解释？
- [ ] **语气合适** — 不是命令式的，而是"我们一起来做"？

## 五、敏感点特别核查

- [ ] **CTF 定位** — CTF 是竞赛/训练形式，不是与取证/渗透并列的安全领域
- [ ] **Cell 制解释** — 讲清楚 Cell 不是部门，是"人+AI=独立生产力单元"
- [ ] **AI 角色** — AI 是工具/员工，人是老板/决策者，不夸大不贬低
- [ ] **零基础成员** — 不让他们感到被边缘化，明确成长路径

---

## 使用方式

1. 写完文稿后，打开此清单
2. 逐项自检，勾上通过的
3. 有问题立即修，不等别人发现
4. 全部通过后再交付
