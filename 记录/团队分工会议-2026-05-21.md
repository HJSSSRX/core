## 一、开场（5分钟）：我们在做什么

### 一句话总结

**forhacker = AI 驱动的网络犯罪综合对抗平台**

覆盖三个核心领域（电子取证、渗透测试、开源情报）+ CTF 竞赛作为实战检验场景 + 大数据分析与信息收集作为支撑能力

### 为什么重来？

旧项目三个致命伤：
1. **Prompt 驱动而非代码驱动** — Markdown 文件堆砌，无法测试、无法版本管理
2. **没有质量门禁** — AI 产出直接进知识库，错误静默累积
3. **文件系统混乱** — prompt、工具、知识、状态全揉在一个目录

### 这次怎么做？

一个词：**架构优先**。过去两天（5月20-21日）完成了：
- 22 项架构决策全部确认
- 设计规格通过 2 轮 × 6 位 AI 审查者审查（51个问题全部修复）
- 实施计划正在编写（5个阶段，~8,200 LOC）

## 二、架构概要（5分钟）：系统的骨架

### 核心理念

```
你（人类）→ 给目标 → Supervisor Agent 分解任务 → 分配给子 Agent 执行
                                                  → 汇总 Findings → 你审核
```

不是你手动操作工具，而是你告诉系统"分析这个磁盘镜像有没有数据泄露的痕迹"，系统自动分解、调度、汇总。

### 六个设计原则（记住这六条就够）

| # | 原则 | 一句话 |
|---|------|--------|
| 1 | **抽象优先，避免锁定** | 每层都有接口+至少两种实现，离线/在线无缝切换 |
| 2 | **程序做搬运，AI做判断** | Syncthing 传文件，AI 只读写本地；绝不写 HTTP 调用 |
| 3 | **置信度分级** | 所有输出标注 ✅已验证 / ⚠️推测 / ❌未知 |
| 4 | **模块自治，核心统一** | 每个插件独立开发，核心只定义接口契约 |
| 5 | **知识是一等资产** | 每个案件自动汇入知识库，越用越强 |
| 6 | **自我改进是基础设施** | MetaAgent 7×24 巡检，发现新工具/新技术/新方法，人类审批后自动升级 |

### 技术栈

- **语言**: Python 3.12（主体）+ Rust/PyO3（性能热点）
- **LLM**: 统一抽象层，支持 OpenAI / Anthropic / DeepSeek / Ollama / vLLM
- **数据**: PostgreSQL（历史查询）+ 本地 YAML 文件（实时协作）
- **协作**: Syncthing（P2P 文件同步）+ Git（代码）
- **隔离**: Docker（常规任务）+ Firecracker microVM（高危任务）

## 三、团队模型（5分钟）：Cell 制

### 不是部门制，是 Cell 制

```
传统部门制:                         Cell 制:
部门长 → 成员1, 成员2, 成员3       每个人 + AI = 独立生产力单元
                                    Cell owner 管自己的 AI 干活
```

**核心理念：成员当小组长，AI 是手下员工。** 你不是来写代码的——你是来指挥 AI 写代码的。

### 仓库分工（GitHub Org: forhacker）

| 仓库 | 需要的人 | 角色 |
|------|---------|------|
| `core/` | **你 + 2位师兄** | 核心框架、接口契约、CI 模板。这是心脏，必须最稳 |
| `plugin-forensics/` | **2位竞赛老手** | 取证插件（内存分析、磁盘分析、文件分析） |
| `plugin-pentest/` | **1老手 + 1新手** | 渗透测试插件 |
| `plugin-osint/` | **1中级 + 1新手** | 开源情报插件 |
| `plugin-ctf/` | **1新手 + AI** | CTF 专项插件（门槛最低，适合练手） |
| `knowledge-base/` | **自动化(CI)** | 共享知识库，代码自动汇入，无需人力 |
| `docs/` | **集体维护** | 中央文档 |

### 三种贡献路径

| 水平 | 人数 | 初始角色 | 成长路径 |
|------|------|---------|---------|
| **有基础** | ~5人 | 插件 owner，管理 AI 开发 | → 核心贡献、架构设计 |
| **有想法** | ~2人 | 核心贡献 + Code Review 辅助 | → 框架设计、技术决策 |
| **零基础** | ~3人 | 测试、文档、报告、跟 AI 学 | → 简单插件 → 独立 Cell owner |

## 四、第一个迭代（10分钟）：Phase 1 任务分解

### Phase 1 概览：Core Skeleton（第1-3周，~2,000 LOC）

**目标**: 搭好骨架，跑通第一条端到端流程——"用 CLI 分析一个内存镜像"。

### 具体任务（按顺序）

#### Task 1: 项目脚手架 [今天就能开始]
**做什么**: `pyproject.toml`、目录结构、`__init__.py`、`tests/conftest.py`
**谁来做**: 你或师兄，30分钟搞定
**产出**: 可以 `pip install -e .` 的空项目

#### Task 2: LLM 抽象层 [核心，需要理解抽象]
**做什么**: `LLMBackend` ABC、`Message`/`LLMResponse` 类型
**谁来做**: 你 + 1位有思想的师兄
**关键**: 这是整个系统的基石——所有 Agent 通过这个接口调 LLM
**测试**: 5个单元测试（抽象类不可实例化、Message字段、Response字段等）

#### Task 3: OpenAI + Ollama 后端实现 [并行]
**做什么**: 对接 OpenAI API 和本地 Ollama
**谁来做**: 1位有Python基础的人 + AI
**关键**: Ollama 用 OpenAI 兼容接口，代码可以很薄

#### Task 4: DeepSeek + Anthropic + 路由 [并行]
**做什么**: DeepSeek（继承OpenAI）、Anthropic（独立实现）、SensitivityRouter
**谁来做**: 1位有基础的人 + AI
**关键**: 路由逻辑：高敏感→本地，低敏感→云端，`FORHACKER_OFFLINE=1` 全局覆盖

#### Task 5: MessageBus [1天]
**做什么**: `MessageBus` ABC + `InProcessBus`（asyncio.Queue）
**谁来做**: 任何人 + AI
**关键**: 默认进程内零依赖，分布式版本后续扩展

#### Task 6: 插件系统 [2天]
**做什么**: `BasePlugin` ABC、`PluginManager`（发现+加载+故障隔离）、`CapabilityRegistry`
**谁来做**: 1位有经验的 + 需要理解插件架构
**关键**: 这是所有插件 Cell 的基础设施

#### Task 7: PostgreSQL 数据层 [2天，可并行]
**做什么**: SQLAlchemy models、数据库迁移、连接管理
**谁来做**: 1位了解数据库的人

#### Task 8: CLI 入口 [2天]
**做什么**: click/typer CLI（`forhacker case create`, `forhacker task run`）
**谁来做**: 任何人 + AI（click 很简单）

#### Task 9: 端到端集成测试 [3天]
**做什么**: 搭一条完整链：CLI → LLM → 工具调用 → Finding 写入
**谁来做**: 你 + 师兄主导
**关键**: 这是 Phase 1 的验收标准——跑通就证明骨架对了

### 分工原则

1. **Task 2-3-4 串行依赖，必须按顺序做**（先定义 ABC，再实现后端，最后路由）
2. **Task 5-6-7-8 可以并行**
3. **零基础成员从 Task 5 和 Task 8 开始**
4. **你控 Task 1、2、9 三个关键节点**
5. **每个 Task 都是"人类决策 + AI 干活"模式**——成员主要负责想清楚需求、审查 AI 产出

## 九、可能会被问到的问题（准备回答）

### Q: 我是零基础，能做什么？
**A**: 先从测试和文档开始。测试是学代码最快的方式——你看测试就知道每个模块应该怎么用。我们每个模块都有 TUTORIAL.md。你有 AI 当私教，不会就问。

### Q: 我们和直接用 ChatGPT/Claude 写工具有什么区别？
**A**: 区别在于系统化和积累。你每次用 ChatGPT 都是一次性的——下次还得重新描述。forhacker 把每次分析的结果自动存进知识库，第二次遇到类似问题直接调取。而且 Supervisor 能自动分解复杂任务，你不用手动把大问题拆成小问题。

### Q: 这个项目怎么参加比赛？
**A**: 线上赛直接用——Supervisor 集中调度，Syncthing 同步答案。线下赛（断网）用本地模型（Ollama），功能完整。你们在 CTF 中用这个平台本身就是最好的测试。

### Q: 服务器 2C8G 20G 够用吗？
**A**: 只跑 PostgreSQL 和 Syncthing 中继——够了。检材在各自电脑上，几百 GB 的镜像不存服务器。后续有经费再扩展。
